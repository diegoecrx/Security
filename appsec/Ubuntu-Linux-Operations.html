Project Operations on Ubuntu Linux

Install, configure, run, sync, deploy and continuously manage a GitHub-hosted project — locally and remotely — using bash on Ubuntu. Covers the toolchain (apt / official repositories), Git/GitHub configuration, the native Docker Engine stack, secrets, multi-machine synchronization, remote repository and pipeline control via the GitHub CLI, deployment, and continuous management with systemd timers.

1Scope & operating model

This runbook operates the SecureBank project (or any equivalent GitHub repository) from bash on Ubuntu. The lifecycle mirrors the Windows runbook: install the toolchain → configure Git/GitHub → clone → run locally → manage secrets → synchronize between machines → control the remote repo and pipelines → deploy → continuously manage.

ElementChoice
Shellbash (default on Ubuntu).
Package managerapt, plus official vendor APT repositories for gh and Docker.
Container runtimeDocker Engine — native on Linux; no VM, WSL or Hyper-V layer. Compose is the docker compose plugin.
Source controlGit + GitHub; remote origin is the single source of truth across machines.
Remote controlGitHub CLI (gh) for repos, PRs, secrets, workflows, releases.
Scheduler / servicessystemd timers (user or system) for continuous management; systemd service to run the stack at boot.

Linux is the native platform for this stack: Docker runs directly on the kernel, and the same Makefile, docker-compose.yml and GitHub Actions workflows work unchanged.

2Toolchain installation (apt)

# Base tools
sudo apt update
sudo apt install -y git make curl ca-certificates gnupg

# GitHub CLI (official APT repository)
sudo mkdir -p -m 755 /etc/apt/keyrings
wget -qO- https://cli.github.com/packages/githubcli-archive-keyring.gpg \
  | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null
sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" \
  | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null
sudo apt update && sudo apt install -y gh

Docker Engine (native) + Compose plugin

# Official Docker APT repository
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Run docker without sudo (log out/in or run 'newgrp docker' to apply)
sudo usermod -aG docker $USER
sudo systemctl enable --now docker

# Verify
git --version; gh --version; docker version; docker compose version
NoteFor stronger isolation, consider rootless Docker (dockerd-rootless-setuptool.sh install) so the engine runs under your user without root. Editor: install VS Code with sudo snap install code --classic if a GUI is available.

3One-time configuration

Git identity and line endings

git config --global user.name  "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --global core.autocrlf input    # keep LF; normalize on commit
git config --global pull.rebase true

Commit a .gitattributes with * text=auto eol=lf so endings are consistent across machines.

GitHub authentication

gh auth login          # choose HTTPS or SSH; credential stored by gh
gh auth status

SSH alternative:

ssh-keygen -t ed25519 -C "you@example.com"
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
gh ssh-key add ~/.ssh/id_ed25519.pub -t "ubuntu-box"
NoteSection 3 is performed once per machine. Everything after it is repeatable and identical on each Ubuntu machine.

4Acquire the project (clone)

# Consistent location on each machine
mkdir -p ~/source
gh repo clone USER/securebank ~/source/securebank
cd ~/source/securebank

# Local .env from the template (never commit the real .env)
cp .env.example .env
nano .env                 # fill in local/fake values

7Synchronize across machines

# Start of a session
git fetch origin
git status
git pull --rebase

# ... make changes ...
git add -A
git commit -m "describe the change"
git push

# On the other machine
git pull --rebase
SituationHandling
Uncommitted work when pullinggit stash → git pull --rebase → git stash pop
Both machines changed maingit pull --rebase; resolve conflicts; git rebase --continue
Check divergencegit log --oneline --graph origin/main..HEAD
Discard local, match remote (destructive)git reset --hard origin/main

Prefer feature branches and PRs over direct commits to main; the sync.sh helper (Section 11) wraps the safe fetch/stash/pull sequence and is driven by a systemd timer in Section 10.

8Remote repo & pipeline control

The GitHub CLI operates the remote entirely from the terminal — identical to the Windows runbook.

# Branches & pull requests
git switch -c feat/x && git push -u origin feat/x
gh pr create --fill
gh pr status
gh pr merge --squash --delete-branch

# Pipelines
gh run list
gh run watch                         # live status of the latest run
gh run view --log
gh run view --log-failed
gh run rerun <run-id>
gh workflow run release.yml          # trigger a workflow_dispatch

# Repository administration
gh secret list
gh run download <run-id> -n sbom
gh release create v1.0.0 --generate-notes

9Deploy

Pipeline-driven (recommended)

gh workflow run release.yml -f environment=production
gh run watch

Deployment to a protected GitHub Environment pauses for approval; the pipeline deploys an immutable, SHA-tagged image.

Manual image build and publish

IMG="ghcr.io/USER/securebank:$(git rev-parse --short HEAD)"
docker build -t "$IMG" ./application/backend
echo "$(pass securebank/ghcr-token)" | docker login ghcr.io -u USER --password-stdin
docker push "$IMG"

Remote deploy over SSH

ssh deployer@deploy-host 'bash -s' <<'EOF'
  cd /srv/securebank
  git pull --rebase
  docker compose -f docker-compose.yml -f compose.prod.yml pull
  docker compose -f docker-compose.yml -f compose.prod.yml up -d
EOF

Run the stack at boot (systemd service)

# /etc/systemd/system/securebank.service
[Unit]
Description=SecureBank stack
Requires=docker.service
After=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/srv/securebank
ExecStart=/usr/bin/docker compose up -d
ExecStop=/usr/bin/docker compose down

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now securebank.service

10Continuous management

Use systemd timers (preferred on Ubuntu) for scheduled sync, maintenance and health checks. User timers need no root; enable lingering so they run without an active login.

Scheduled auto-sync (user timer)

# ~/.config/systemd/user/securebank-sync.service
[Unit]
Description=Sync securebank from origin
[Service]
Type=oneshot
ExecStart=%h/source/securebank/scripts/sync.sh

# ~/.config/systemd/user/securebank-sync.timer
[Unit]
Description=Daily securebank sync
[Timer]
OnCalendar=daily
Persistent=true
[Install]
WantedBy=timers.target
loginctl enable-linger $USER                 # run user timers without a session
systemctl --user daemon-reload
systemctl --user enable --now securebank-sync.timer
systemctl --user list-timers

Health monitor (restart if unhealthy)

#!/usr/bin/env bash
if ! curl -fsS http://localhost:8000/health > /dev/null; then
  docker compose restart api
  echo "$(date -Is) restarted api" >> ~/source/securebank/logs/health.log
fi

Enable OS auto-patching: sudo apt install unattended-upgrades && sudo dpkg-reconfigure --priority=low unattended-upgrades.

11Helper scripts

Keep operational scripts in scripts/ in the repo so both machines share them; make them executable (chmod +x). They complement the Makefile targets.

ScriptPurpose
setup.shInstall toolchain (apt), configure git/gh, create .env.
sync.shSafe fetch → stash → pull --rebase → stash pop.
up.sh / down.shStart / stop the compose stack.
deploy.shBuild, tag by SHA, push to GHCR, trigger/await the release.
scan.shRun local scanners into reports/.
 
#!/usr/bin/env bash
# scripts/sync.sh — safe synchronization
set -euo pipefail
cd "$(dirname "$0")/.."
dirty=$(git status --porcelain)
[ -n "$dirty" ] && git stash push -u -m sync-autostash || true
git fetch origin
git pull --rebase origin "$(git rev-parse --abbrev-ref HEAD)"
[ -n "$dirty" ] && git stash pop || true
echo "Synced $(git rev-parse --short HEAD)"
Noteset -euo pipefail makes scripts fail fast so systemd timers and CI detect errors. Mark scripts executable and keep them idempotent and safe to re-run.

12Troubleshooting

SymptomCause / resolution
permission denied on docker socketUser not in the docker group. sudo usermod -aG docker $USER, then re-login or newgrp docker.
Cannot connect to the Docker daemonEngine not running. sudo systemctl enable --now docker.
Port 8000 already in usesudo ss -ltnp | grep :8000 → stop the owner or change the mapped port.
Script not executablechmod +x scripts/*.sh; run with ./scripts/sync.sh or bash scripts/sync.sh.
User timer did not fireEnable lingering: loginctl enable-linger $USER; check systemctl --user list-timers and journalctl --user -u ....
gh: not authenticatedgh auth login / gh auth status.
Rebase conflict during pullResolve files, git add, git rebase --continue; or git rebase --abort.
